# v0.9 执行方案 — 生产就绪加固

> 状态：决策已拍板，待实现
> 范围：生产 Tier-1 缺口收口（状态持久化 + 鉴权硬化 + SSE 健壮性）

## 一、决策点（用户拍板，2026-09-16）

| 决策点 | 选项 | 理由摘要 |
|---|---|---|
| A1 持久化存储 | **Redis** | 重启不丢、并发强；代价是新增服务。本地无 Redis 时降级内存态 + 启动告警，不阻断启动。 |
| A2 chat 未建 session | **惰性创建** | chat 时自动建 session，客户端无需先 `POST /sessions`；代价是仍可能产生脏名（但可被 `POST /sessions` 显式创建覆盖，且 history 不受影响）。 |
| A3 加固范围 | **全做** | 状态持久化 + session 校验 + 修 #19 SSE 晚连接挂死 + 修 #21 缺头 422→401，一次到位。 |

## 二、目标

1. turn 注册表、审批请求（approval）落 Redis，进程重启后可恢复（history 仍作兜底事实源）。
2. chat 收到未建 `session_id` 时惰性创建，行为顺滑且不再有"任意字符串触发执行却不记录"的隐患。
3. 鉴权语义符合 REST：缺 `X-API-Key` 或值错均返 **401**（原仅值错 401、缺头 422）。
4. SSE 晚连接（任务已结束才订阅 `/events`）收到 `final`/`error` 后正确关闭流，客户端不再永久挂起。

## 三、子任务与改动

### 子任务 1 — 状态持久化（Redis）
- 新增 `api/state_store.py`：封装 Redis 连接（`REDIS_URL`，默认 `redis://localhost:6379`）。
  - 启动时探测可用性：`ping()` 成功 → 持久化开启；失败 → 降级内存 `dict` + 启动 `WARNING` 日志（不阻断启动）。
  - 提供 `TurnRegistry` / `ApprovalRegistry` 两套接口，内部在 Redis 可用时读写 Redis（hash / stream / 带 TTL），不可用时退回现有内存实现。
- `api/worker.py`：turn 注册表改用 `state_store`；`POST` 消费分离逻辑不变，注册/查询走新接口。
- `tools/verify_tools.py`：审批注册表 `register_request/get_request/cleanup_request/try_claim/finalize` 改走 `state_store`（保持 `try_claim` 原子占位，Redis 用 `SET NX` 实现）。
- `pyproject.toml`：加 `redis>=5.0`；`.env.example` 补 `REDIS_URL`。

### 子任务 2 — Session 惰性创建（#29）
- `api/server.py` 的 chat 路由：进入 worker 前 `SessionManager.get_or_create(session_id)`（不存在则 `create_session` 并记录 `created=true` 日志），再以该 session 提交 turn。
- 不再把任意字符串当"已存在 session"静默使用；保留 `/api/sessions` 显式创建能力。

### 子任务 3 — 鉴权 401 语义（#21）
- `api/server.py` 的 `require_api_key`：用 `Header(alias="X-API-Key")` 取到的值若为 `None`（缺头）→ 显式 `raise HTTPException(401, "Missing API key")`；值存在但不匹配 → 维持 `401`。使缺头/错头均 401，符合 REST。
- `/health` 仍豁免。

### 子任务 4 — SSE 晚连接修复（#19）
- `api/server.py` 的 `/events` 回放循环：抽到 `final` / `error` 终态事件时 `break`（与实时分支共用同一"终止即断"判断函数），覆盖 replay 与实时两条路径；晚连接不再无限 `: ping`。

## 五、验证计划（E2E）

1. **持久化**：起服务→发代码任务→等审批/完成→`POST /approve`→重启服务→`GET /tasks/{id}` 与 `/events` 仍能回放（Redis 可用时）；停 Redis 重启→服务仍起、日志告警、功能可用（降级）。
2. **惰性 session**：用新 `sid` 直接 chat→返回正常 turn_id，`GET /sessions` 可见该 session 已建。
3. **401**：`curl` 不带 key → 401；错 key → 401；`/health` 无 key → 200。
4. **SSE 晚连接**：任务跑完后才连 `/events` → 回放 `final` 后流关闭（非永久 `: ping`）。
5. **回归**：普通对话、KB 检索、v0.7 成本日志、v0.8 沙箱 + HITL 审批均不回归（每版冒烟必含一次真实代码任务）。

## 六、已知边界

- Redis 降级时持久化失效（靠 history 兜底），属预期；部署生产须保证 Redis 可用。
- 惰性创建仍可能产生脏 session 名（无害，可被显式创建覆盖）；未来如需强约束再开严格 404。
- 出网/CPU 限额、CORS、HTTPS 反代不在本期（留 v1.0 或独立运维项）。
- 完整工具级权限模型（蓝图原 v0.9）已顺延，本期只做基础设施加固，不引入权限策略层。
