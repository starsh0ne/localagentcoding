# v0.8 执行方案 — 代码执行隔离沙箱（含 HITL 审批闸）

> 版本号决策：本版定为 **v0.8.0**（覆盖原蓝图的「v0.8 权限注册」）。原蓝图 v0.8 权限注册顺延为 **v0.9**——其能力之一「危险操作审批闸」已在本版以基础形态（HITL 执行确认）落地；完整的工具级读/写/执行权限模型留待 v0.9 细化。

## 1. 范围决策（用户 2026-09-11 拍板，含优缺点权衡）

| 决策点 | 选定 | 备选与权衡 |
|--------|------|-----------|
| 隔离技术 | **WSL2 子环境** | Docker（隔离最强，但需装 Desktop、冷启动慢、镜像维护重）；受限子进程（零依赖、快，但同 OS 用户、能读宿主机 .env、网络/资源不限，只能防误用） |
| 触发范围 | **仅 coder 自验/测试** | 全部 exec 工具（全面但工作量大、影响 pip/run 正常功能）；仅危险操作（折中但需界定「危险」、普通读仍暴露） |
| 网络策略 | **允许出网（pip 可用）** | 完全禁网（最安全但 coder 测试装不了依赖）；白名单域名（平衡但需维护、可能误拦） |
| HITL 审批 | **执行前需确认** | 全自动不确认（流畅但危险代码直接执行风险高） |

**综合判断**：中等强度隔离 + 最小触发面 + 人工把关 = 在「个人单机、功能优先」前提下，以最小代价补上生产安全底线，并直接消化 backlog #24（交付物无验证关卡）。

## 2. 目标
- 让 coder 在**交付前**对生成的代码做自验（跑测试 / 执行），执行发生在 **WSL2 隔离子环境**，网络放行（pip 可用），且**每次执行前需用户确认**。
- 普通对话（general / 非 coder 路径）不进沙箱，行为不变。
- 不追求 Docker 级强隔离：本版隔离定位为「防误用 + 基础进程/目录隔离」，针对性恶意代码防护留待后续上 Docker（已在决策权衡中明示）。

## 3. 设计要点

### 3.1 隔离层：`sandbox/wsl_exec.py`（新增）
- `run_in_wsl(command: str, cwd_win: str, timeout: int = 120) -> SandboxResult`
  - 路径映射：`cwd_win`（如 `C:\...\workspace\pomodoro`）→ WSL 路径 `/mnt/c/.../workspace/pomodoro`；命令在 WSL 该目录下执行。
  - 执行载体：`subprocess.run(["wsl.exe", "bash", "-lc", <mapped_cmd>], cwd=<wsl_path>, timeout=...)`，捕获 stdout/stderr（截断到合理上限，如 20KB）。
  - 超时：硬上限 `timeout` 秒，超时杀进程并返回超时标记（避免长任务卡死串行 worker）。
  - 资源：本版不强制 cgroup/CPU 限额（WSL 用户空间天然轻隔离）；超时即主要资源护栏。
  - 隔离保证：代码运行在 WSL 用户空间；工作根锁定为 workspace 子目录；`.env` 等宿主机凭据**不主动挂载**进沙箱工作根。明确边界：WSL 默认可挂 `/mnt/c`，故本版不防「针对性恶意代码读 Windows 盘」——此点属已知边界（见 §6）。
- 探测：启动时检测 `wsl.exe --list` 可用性，不可用则沙箱执行器降级为「拒绝 + 明确错误」（不静默回退宿主机执行）。

### 3.2 审批闸（HITL）：阻塞式等待（本版简化实现）
- 新增 coder 工具 `request_verification(command: str, note: str)`：
  - 调用时不执行，仅 publish `tool_call` 事件（`needs_approval=true` + 命令预览 + note），并**挂起当前 worker 线程**（`threading.Event.wait(timeout=300)`）。
  - 新增 API：`POST /api/turns/{turn_id}/approve`，body `{"approve": bool, "comment": ""}`：
    - `approve=true` → worker 在 WSL 执行该命令，输出作为工具返回值，agent 继续 stream；
    - `approve=false` → 返回拒绝原因，agent 调整方案；
    - 超时未审批 → 自动拒绝，agent 跳过自验并说明。
- 串行 worker 单线程：一个 turn 等待审批时整队阻塞——个人单机可接受（本就一次一个）；此限制记入已知边界，后续可升级为真正异步中断（LangGraph `interrupt()`）。
- 事件：审批请求/结果通过现有 SSE 总线 `turn:{turn_id}` 话题推送，前端/客户端可见。

### 3.3 触发范围：仅 coder 自验
- **不改** coder 生成文件的行为（文件落在 workspace，本身安全）。
- 在 coder 工作流加一步「交付前自验」：生成代码后调用 `request_verification` 跑测试/执行（解 #24）。
- general / 其它路径不挂载 `request_verification`，无沙箱、无审批。

### 3.4 网络：允许出网
- WSL 默认出网，沙箱不阻断；`pip install` 可正常装依赖。
- 已知边界：允许出网意味着数据外泄理论可能（见 §6）。

## 5. 实施步骤
1. `sandbox/wsl_exec.py`：实现 `run_in_wsl` + WSL 可用性探测（单测：映射路径正确、超时返回、无 WSL 时降级报错）。
2. `tools/verify_tools.py`：`request_verification` 工具（发布事件 + `Event.wait` 挂起 + 结果回填接口）。
3. `api/server.py`：`POST /api/turns/{turn_id}/approve` 端点（校验 turn 存在 + 鉴权）。
4. `api/worker.py`：审批状态机接入（挂起 / 执行 / 拒）；`approve` 时调 `run_in_wsl` 回填。
5. `agents/coder.py`：工作流加自验步 + 挂载工具 + 提示词约束。
6. 日志：自验走 sandbox 时记 `event_kind="sandbox_exec"`（复用 v0.7 `cost_summary` 同款上下文）。
7. 端到端验证（§6）。

## 6. 验证（手动，用户执行）
- 起 API → 建 session → 发「用 Python 写单文件番茄钟 CLI 到 workspace/pomodoro/ 并自验」→ 订阅 events：
  - 应看到 `tool_call(dispatch_to_coder)` → coder 生成文件 → `tool_call(request_verification, needs_approval=true)`（命令预览）→ **此时 turn 挂起**。
  - 另终端 `POST /api/turns/{id}/approve {"approve":true}` → 沙箱在 WSL 跑测试 → 输出回传 → coder 总结。
  - 检查 `logs/agent_pro.log`：`sandbox_exec` 事件含 `sandbox="wsl2"`、命令、退出码、耗时。
  - 隔离抽检：自验命令里尝试 `cat /mnt/c/Users/26024/.env` 应**失败或读不到**（验证工作根锁定 + 提示词约束生效；WSL 能挂盘属已知边界，靠提示词+工作根约束降低风险）。
- 回归：普通对话（非代码）不触发审批、不进沙箱；v0.5 鉴权 / v0.6 KB / v0.7 日志成本不受影响。

## 7. 已知边界（本版明确不做 / 留后续）
- **隔离强度**：WSL2 子环境 = 中等隔离（防误用 + 进程/目录隔离），不防针对性恶意代码读 Windows 盘（WSL 默认挂 `/mnt/c`）。强隔离（Docker/nsjail/gVisor）留 v0.9+ 或按需单独版本。
- **串行阻塞**：审批等待时整队挂起（个人单机可接受）；真正异步中断（LangGraph `interrupt()`）留后续。
- **网络**：允许出网，数据外泄理论可能；白名单域名留后续。
- **权限模型**：完整工具级读/写/执行权限（原蓝图 v0.8）→ 顺延 v0.9；本版仅落地「执行确认」这一闸。
- **资源限额**：本版仅超时护栏，无 CPU/内存硬限额；限额留后续。
