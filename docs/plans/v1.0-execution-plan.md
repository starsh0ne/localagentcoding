# v1.0 并发改造执行方案

> 目标：把 v0.9 的**单进程串行队列**（同时仅 1 个 turn 执行）改造为**可配置并发 worker 池**，
> 让"多 Agent 任务闭环"真正支持并行执行，并补齐"连接复用改造"与"真实 RAG 命中率"，
> 使简历中"稳定支撑高并发"与"检索命中率"两项陈述**有据可依**。

## 决策点（已与用户拍板）

| 编号 | 决策 | 选择 | 理由 |
|---|---|---|---|
| B1 | 并行模型 | **单进程 worker 池 + Redis 队列/状态后端**，SSE 事件总线留进程内 | 改动最小、进程内 bus 直接复用最稳；Redis 仅做队列/状态后端（重启可恢复） |
| B2 | venv 隔离 | **保留共用 venv，不做独立 venv**；`pip_install` 加全局锁防并发污染 | 每任务 venv 每次新建慢数十秒；共用环境+安装锁够用，真隔离留作债务 |
| B3 | SQLite | **每线程持有一个连接 + WAL** | 真正"连接复用"；修正并行下共享单连接的非线程安全；WAL 多读不阻塞 |
| B4 | 评测 | **实现 eval/runner.py + 内置黄金集，跑真实命中率** | 原 eval 是空壳；用真实数字替换简历里的 85% |

## 子任务与文件变更

1. **新增 `src/agent_pro/api/queue.py`** — `TurnQueue` 抽象
   - `MemoryTurnQueue`：包 `asyncio.Queue`（无界，行为同现状）。
   - `RedisTurnQueue`：`put`=rpush；消费者 `await asyncio.to_thread(redis.brpop, key)` 阻塞取；任务留 Redis → 重启可恢复。
   - `get_turn_queue()`：`queue_backend`(auto/redis/memory)；auto 时 Redis 可用用 Redis，否则降级 Memory 并告警（对齐 `state_store` 降级风格）。
2. **改 `src/agent_pro/api/worker.py`**
   - `run(concurrency)` 起 N 个消费者协程；每个 `turn=await queue.get(); await asyncio.wait_for(asyncio.to_thread(_execute), timeout=turn_timeout_s)`。
   - `submit` 改调 `queue.put(turn)`（后端无关）；单 turn 异常不退出消费者。
3. **改 `src/agent_pro/api/server.py`** — `lifespan` 起 `settings.worker_concurrency` 个 worker 消费者；保留单 event bus。
4. **改 `memory/store.py`、`kb/store.py`、`tasks/store.py`** — 单连接 → 每线程连接（`threading.local` 缓存复用）+ WAL。
5. **改 `tools/env_tools.py`** — `pip_install` 加全局 `threading.Lock` 串行化安装。
6. **改 `config.py`** — 新增 `worker_concurrency=4`、`turn_timeout_s=600`、`queue_backend="auto"`、`eval_dataset_path`；`__init__.py` 版本 `0.9.0→1.0.0`。
7. **实现 `eval/runner.py` + 新增 `eval/gold_dataset.json`** — 加载数据集→逐条跑 general agent→统计 引用命中率/准确率/延迟/成本；本环境可出网跑 DeepSeek 拿真实 `citation_hit_rate`。

## 验证计划（E2E）

- **并发/队列/SQLite 单测**（已落地，合并为 `tests/test_v1_concurrency.py`）：
  - `test_queue_memory_order`：Memory 后端顺序正确。
  - `test_worker_pool_parallel`：submit 多个 turn（fake execute），断言时间窗重叠（并行）。
  - `test_memory_store_per_thread_conn`：6 线程并发读写不报错（连接复用改造）。
- **eval 真跑**：对黄金集跑 general agent，输出 `EvalReport`（含真实 `citation_hit_rate`）。
- **集成烟测**（待 Redis 环境）：起 server，并发 POST 多个 chat，观察 N 个 turn 并行，SSE 正常。

## 实现期发现并修复的真实缺陷（属 v1.0 必改）

- **`search_knowledge` 未挂载到通用 agent**：`agents/general.py` 的 system prompt 指示模型"涉及私有笔记/规范 → search_knowledge"，
  但该工具虽被 import 却从未加入工具列表，导致 RAG 检索对通用 agent 完全失效，"回答逐条可溯源"名不副实。
  v1.0 已把 `search_knowledge` 接入通用 agent 工具集，eval 引用命中率方才可得。

## 已知边界（简历须如实表述）

- **共享 venv**：并行 coder 的 pip 安装经全局锁串行，但运行时仍共用同一环境；两任务要求互斥依赖版本会冲突（债务：未来 per-task venv）。
- **Redis 路径**：本环境无 Redis，仅验证 Memory 后端降级；Redis 队列/状态路径需在装 Redis 环境复核（同 v0.9 `state_store`）。
- **"100 并发"**：worker 池使并发执行数 = N（可配，默认 4，资源+LLM 配额够可上 100）；真·100 并发稳定取决于 DeepSeek RPM/TPM 与单机资源。简历表述改为"可配置并发 worker 池，稳定支撑数十~百级并发提交与并行执行"。
- **HITL 已带 `APPROVE_TIMEOUT_S=300` 超时**，加 `turn_timeout_s` 后单 turn 不再无限占槽。
