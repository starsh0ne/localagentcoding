# v1.1 记忆系统完善 — 执行方案

> 决策已由大老师拍板（2026-10-22）：
> B1 隔离 = **user + project + agent 三层全加**
> B2 取回 = **摘要常驻 + 每轮语义检索 top-k**
> B3 存储 = **继续 SQLite，检索对齐 KB 的 RRF 混合**
> B4 分层 = **保持短期+长期两层，只补齐召回/隔离/TTL**

## 一、现状（调研确认，勿凭记忆）

- `memory/store.py`：短期 = `messages` + `sessions.summary`；长期 = `long_term_memories`
  （`kind, content, embedding, source_session, created_at`）+ `memory_fts` 虚拟表。
- `KINDS = ("preference", "fact", "entity")`（`store.py:18`）。
- 隔离：**仅 session 一级**；`user_id / project_id / agent_id` 全库 0 命中。
- 长期记忆**只在压缩时由 LLM 提取写入**（`manager.py:76-77`）。
- 取回：`worker.py:175` → `manager.py:47-64` 的 `_context_message()`，
  每轮固定灌「摘要 + 全部 preference（limit=20）」，**非语义检索**。
- `search_memories()`（`store.py:176`）在生产代码**零调用**（死代码）→ `fact`/`entity` 读不到。
- **真实缺陷**：`store.py:190` 调用 `_cosine(...)`，但导入的是 `cosine`
  → 一旦配置 embedding，向量分支必抛 `NameError`。
- 检索质量落后同项目 KB 一档：KB 已实现 RRF 混合（`kb/store.py:117-121`，k=60、候选 20），
  记忆侧是「有向量只用向量 / 否则只用 FTS」的互斥降级 + LIKE 兜底。
- `memory/session.py` 为空壳 TODO（若仍无引用则删除）。

## 二、变更设计

### 2.1 隔离（B1）

`sessions` 与 `long_term_memories` 两张表均新增三个作用域列 + 索引：

```sql
user_id    TEXT NOT NULL DEFAULT 'default'
project_id TEXT NOT NULL DEFAULT 'default'
agent_id   TEXT NOT NULL DEFAULT 'default'
CREATE INDEX idx_ltm_scope ON long_term_memories(user_id, project_id, agent_id, kind);
```

- 旧数据迁移：三列取默认值 `'default'`（保证向后兼容，不丢数据）。
- 所有长期记忆的读写查询**必须带作用域条件**，禁止再出现无作用域的全表取。
- `source_session` 保留为溯源字段，不参与隔离。

### 2.2 取回（B2）

`manager.py::_context_message()` 改为两段式：

1. 会话摘要**常驻**（短期层，行为不变）；
2. 长期记忆按**当前 query 做语义检索 top-k**，与摘要拼接。

- 语义检索必须覆盖 `preference / fact / entity` 三类（现状只取 preference）。
- top-k 由配置 `memory_recall_top_k` 控制（默认 5）。

### 2.3 检索实现（B3）

`memory/store.py::search_memories()` 重写为 **RRF 混合**，对齐 `kb/store.py`：

- 向量候选 top-20 + FTS5 候选 top-20 → RRF 融合（k=60）→ 取 top-limit；
- 任一路径不可用（未配 embedding / 熔断中）时**仍能靠另一路返回**，不再是互斥降级；
- **同时修掉 `_cosine` → `cosine` 的 NameError**（`store.py:190`）。
- 不引入 Chroma / FAISS 等新依赖。

### 2.4 有效期（B4 附带）

- `long_term_memories` 新增 `expires_at TEXT NULL`；
- 配置 `memory_default_ttl_s`（默认 `0` = 永不过期）；
- 提供 `purge_expired()`，在检索时顺带清理过期条目（不额外起定时任务）；
- 过期条目不得被召回。

### 2.5 API 契约

- `POST /api/sessions`：body 可选 `user_id / project_id / agent_id`（默认 `'default'`），
  会话创建时把作用域写入 sessions 表。
- `POST /api/sessions/{sid}/chat`：body 可选同三字段；未传则回退到该会话创建时的作用域。
- 保持既有 `session_id` 长度校验（≤128）与 `message` 长度校验（≤100000）。

### 2.6 新增配置项（`config.py`）

| 配置 | 默认 | 说明 |
|---|---|---|
| `memory_recall_top_k` | `5` | 每轮长期记忆语义召回条数 |
| `memory_default_ttl_s` | `0` | 长期记忆默认有效期（0=不过期） |
| `memory_rrf_k` | `60` | RRF 融合系数，与 KB 保持一致 |

## 三、不做（明确边界）

- 不新增 working memory / episodic 层（B4 已定保持两层）。
- 不引入外部向量库（B3 已定继续 SQLite）。
- 不改短期记忆的压缩触发机制（仍按轮数，不看 token）。
- 语义级去重仍记为债务，本次不做。

## 四、验收标准

1. **隔离**：不同 `user_id`（或 project / agent）写入的长期记忆互不召回；
   不传作用域时走 `'default'`，行为与改动前一致（向后兼容）。
2. **召回**：`fact` / `entity` 类记忆可被检索到（现状读不到）。
3. **RRF**：配置 embedding 时向量路径可用且**不抛 NameError**；
   未配置或熔断中仍能从 FTS 路径返回结果。
4. **TTL**：`expires_at` 已过期的条目不被召回，且会被清理。
5. **回归**：既有 23 项测试全部仍通过。
6. **API**：两个端点接受可选作用域字段并正确落库。
